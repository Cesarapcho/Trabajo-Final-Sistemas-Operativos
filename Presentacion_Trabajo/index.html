02 Resumen Ejecutivo

¿Qué investigamos?

Objetivo Central

Desarrollar un simulador en Python para implementar y comparar cuatro algoritmos clásicos de planificación de CPU bajo los mismos escenarios de carga.

Metodología

Ejecución de un mismo conjunto de procesos en cada algoritmo. Cálculo automatizado de métricas y generación de diagramas de Gantt y gráficos comparativos.

Hallazgo clave

No existe un algoritmo universalmente superior. La eficiencia depende de la carga de trabajo y los objetivos del sistema.

SJF → menor espera RR → más equitativo FCFS → efecto convoy

03 Definición del Problema

Contexto e Importancia

🖥️ El Problema

En sistemas multiprogramados, la cantidad de tareas que demandan tiempo de cómputo supera la capacidad física del procesador, generando colas de espera y cuellos de botella.

⚠️ Sin planificación adecuada...

  • Latencia excesiva para el usuario
  • "Efecto convoy" → procesos cortos bloqueados
  • Inanición (starvation) de procesos
  • Degradación de la capacidad de respuesta

🎯 Objetivos Específicos

  • Diseñar estructura de datos para modelar procesos en Python
  • Implementar los 4 algoritmos bajo el mismo escenario
  • Calcular métricas: tiempo de espera, retorno y utilización de CPU
  • Generar diagramas de Gantt y gráficos comparativos

📐 Alcance

Simulación matemática teórica. No contempla variables físicas (context switch, fallos de página, operaciones I/O). Procesos con ráfagas continuas y estáticas.

04 Marco Teórico

Conceptos Fundamentales

⚙️

Sistema Operativo

Conjunto de programas que actúa como intermediario entre el usuario y el hardware, administrando eficientemente los recursos físicos y lógicos del sistema.

🔄

Proceso

Unidad básica de trabajo del SO. Un programa en estado de ejecución. Transita por estados: Listo → Ejecución → Bloqueado, gestionado mediante el PCB.

🗓️

Proceso por el cual el SO determina qué tarea lista obtendrá el procesador. El scheduler maximiza la multiprogramación y balancea equidad y velocidad.

05 Algoritmo FCFS
📋

FCFS

First Come, First Served

¿Cómo funciona?

La CPU se asigna a procesos en el orden estricto de llegada, mediante una estructura FIFO. Es no apropiativo: el proceso retiene la CPU hasta finalizar.

⚠️ Efecto Convoy

Procesos cortos experimentan tiempos de espera excesivos si un proceso largo acapara la CPU.

def FCFS(llegada, ejecucion): tiempo = 0 for i in range(len(llegada)): if tiempo < llegada[i]: tiempo = llegada[i] espera[i] = tiempo - llegada[i] tiempo += ejecucion[i] retorno[i] = espera[i] + ejecucion[i]
06 Algoritmo SJF
⚡

SJF

Shortest Job First

¿Cómo funciona?

Asigna la CPU al proceso con la ráfaga más corta disponible. Es matemáticamente óptimo: minimiza el tiempo de espera promedio para cualquier conjunto.

⚠️ Limitación

Riesgo de inanición (starvation) para procesos largos si llegan continuamente tareas cortas. Requiere conocer el tiempo de ráfaga de antemano.

07 Algoritmo Round Robin
🔁

Round Robin

Tiempo Compartido (quantum)

¿Cómo funciona?

Cada proceso recibe un quantum de tiempo (10–100 ms). Si no termina, es interrumpido y se reinserta al final de la cola circular. Es apropiativo.

🎛️ El quantum es crítico

  • Quantum grande → se comporta como FCFS
  • Quantum pequeño → sobrecarga por context switch

08 Planificación por Prioridades
🏆

Prioridades

Por nivel de importancia

¿Cómo funciona?

Cada proceso tiene un valor numérico de prioridad. El planificador siempre selecciona el proceso de mayor prioridad (menor valor numérico) disponible.

⚠️ Inanición (Starvation)

Procesos de baja prioridad pueden esperar indefinidamente. Solución: técnica de envejecimiento (aging) que incrementa gradualmente la prioridad.

14 Conclusiones y Recomendaciones

Hallazgos Finales

🏅 Algoritmo más eficiente: SJF

Menor tiempo de espera promedio (7 u.) y retorno (15 u.), cuando se conoce la ráfaga de CPU de antemano. Óptimo en teoría, pero de difícil aplicación práctica.

⚖️ Más justo en la práctica: Round Robin

Mejor capacidad de respuesta en sistemas interactivos. El quantum adecuado es el factor clave para equilibrar equidad y overhead de context switch.

🔑 Conclusión General

No existe un algoritmo universalmente superior. La eficiencia depende de la carga de trabajo y los objetivos del sistema (throughput vs. tiempo de respuesta).
